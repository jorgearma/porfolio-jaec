    01/tcpfilteredopenapi-auditfreelance · cliente real · nov 2025

    Pentest de API · cliente real

    anexo 01-A write-up↗ github.com/jorgearma/api-security-assessment

    Cualquiera en Internet podía leer, modificar y borrar los datos personales de cualquier usuario, y usar gratis la IA de pago del cliente. Lo encontré en la API en producción de una plataforma web con IA (empresa de software, LATAM), en 5 días y como freelance.

    Empecé en caja negra: el fuzzing destapó la documentación OpenAPI expuesta en producción, y con ella el mapa completo de la API. Probé el control de acceso endpoint por endpoint con Burp Suite y curl, y limité las escrituras a un registro que creé yo: ningún dato real tocado. Tras los primeros hallazgos, el cliente me abrió el código.

    Con el código encontré la causa raíz (la validación del token existía, pero solo en algunos endpoints) y propuse aplicarla a nivel de router, reutilizando lo que ya había. También ajusté la severidad con evidencias: rebajé un hallazgo que desde fuera parecía crítico y subí otro por su impacto económico, que CVSS no mide. Publicado anonimizado, con autorización del cliente.

    1. 01 Recon · /docs expuesto fuzzing → OpenAPI en producción → mapa completo de la API
    2. 02 BOLA · crítica leer, editar y borrar datos personales de cualquier usuario por ID
    3. 03 BFLA · crítica CRUD completo de equipos sin token, incluida carga masiva por CSV
    4. 04 IA de pago como proxy público sin auth ni límites: CVSS 7.5, crítica por impacto de negocio
    5. 05 Caja gris · remediación causa raíz en el código, severidad ajustada y fix a nivel de router

    02/tcpfilteredopenad-labnordwind.local

    Nordwind AD Lab

    anexo 02-A github↗ anexo 02-B ▶ playver replay↗ github.com/jorgearma/nordwind-ad-lab ad-lab.jorgearmandoescobar.com

    Monté un dominio de Active Directory desde cero, lo saboteé a propósito y lo ataqué de cero credenciales a Domain Admin y DCSync completo. Los dos lados de AD: construir, romper y entender.

    Para explotar bien un entorno hay que saber cómo está hecho. Levanté el dominio limpio (DC + cliente, modelo AGDLP), planté las misconfiguraciones y las exploté desde Kali — todo manual, con impacket, netexec y hashcat, sin Metasploit. Metodología OSCP.

    Y no me quedo en el exploit: cada paso documenta por qué funciona, cómo se corrige y cómo se detecta (con sus Event IDs). También la mirada del que defiende.

    1. 01 AS-REP Roasting sin credenciales → piotr.wisniewski
    2. 02 Kerberoasting cuenta de servicio svc_sql
    3. 03 Cadena de ACL ForceChangePassword → GenericAll → Domain Admins
    4. 04 DCSync hashes de krbtgt y Administrator
    5. 05 BloodHound post-mortem: análisis de rutas

    03/tcpfilteredopenpanchi-botcase study

    Panchi-Bot

    anexo 03-A landing↗ anexo 03-B recdemo en vivo↗ panchibot.es panchibot.es/demo

    Bot de pedidos por WhatsApp con cobro online, diseñado, construido y asegurado por mí. Cubre todo el ciclo del pedido: del primer mensaje del cliente al cobro y la entrega.

    Lo diseñé pensando en cómo lo atacaría: pagos con Monei, webhooks públicos, WebSockets en tiempo real y cuatro roles con privilegios distintos (admin, cocina, picking y reparto). El pago solo lo confirma el servidor, la autorización se comprueba por rol en cada endpoint y las direcciones se validan con geofencing y un catálogo cerrado de calles, nunca con texto libre.

    Backend Flask en capas estrictas, mensajes procesados en segundo plano con Redis Queue y registro de usuarios con máquina de estados para que no se puedan saltar pasos. En producción en www.panchibot.es sobre mi propio VPS, detrás de Cloudflare Tunnel.

    Docker Deploy

    github

    # despliegue seguro con docker + nginx

    Guía y configs de referencia para escribir un Dockerfile, un docker-compose y un nginx.conf endurecidos, basadas en la OWASP Docker Security Cheat Sheet y probadas atacándolas desde dentro.

    • → plantillas sin root, read-only, cap_drop ALL, no-new-privileges y puertos solo en 127.0.0.1
    • → scripts de verificación: contenedor, nginx desde fuera y host; cada línea sale como OK, FALLO, AVISO o MANUAL con su regla OWASP
    • → pruebas activas de post-explotación: escritura en /, noexec, binarios SUID y secretos en docker history

    04/b · threat intel en producción

    Siege Map

    github demo

    # mapa en tiempo real de ataques SSH y HTTP

    Lee los logs de SSH y Nginx de un VPS, geolocaliza cada IP y la pinta en un mapa mundial con arcos animados hacia el servidor.

    • → clasifica cada atacante (diccionario, credential stuffing, password spraying, sondeo) con TTPs de MITRE ATT&CK
    • → ficha por IP con ASN, reputación de AbuseIPDB y puntuación de amenaza
    • → exporta a STIX 2.1 y CSV; las IPs de visitantes HTTP se guardan truncadas a /24
